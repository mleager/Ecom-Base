# Release 1.0.0 (`ecom-base`)

The first release of Project 1: Milestones 1–17 plus the fixes from the final database and Terraform reviews. It is tagged **`base-v1.0.0`** and published as **`ghcr.io/mleager/ecom-base:1.0.0`**. Later portfolio projects run this image, or fault variants of it published as `ghcr.io/mleager/ecom-<variant>`; the image's `io.github.mleager.ecom.variant` label is `base`.

To run it, see [HOW_TO.md, "The release image"](../HOW_TO.md#7-the-release-image).

## What it contains

- One image that serves the API and the built React app from one HTTPS origin, plus the `migrate`, `db-bootstrap`, `reconcile` and `maintain` commands.
- Readiness for a CDN and several API tasks: trusted CloudFront viewer address, rate limits shared in PostgreSQL, IPv6 prefix limits, guest idle expiry and refresh-token reuse detection.
- A Terraform development stack on AWS ([terraform/DESIGN.md](terraform/DESIGN.md)).
- Final review fixes:
  - `db-bootstrap` sends PostgreSQL only SCRAM verifiers, so a failing `ALTER ROLE` can't log a password.
  - `ecom_app` has role-level statement, lock and idle-in-transaction timeouts.
  - The apply waits for the API rollout and publishes the SPA only after it.
  - The ALB checks liveness, so a database outage no longer replaces every task.
  - Instances refresh on a rolling basis when the AMI changes.

## Known limits

**Image and build**
- Builds are not bit-for-bit reproducible. Consumers pin the published digest; `release-evidence.sh` refuses to replace an existing tag.
- No in-container health check (distroless has no shell); probe `/health/ready` from outside.
- In the Compose deployment, env-file secrets are visible to anyone who can run `docker inspect` on the host.

**Application**
- The SMTP exchange has a fixed 2-second budget with no retry. The user sees "unconfirmed" and can send again.
- A database outage shows as `500 internal_error` on most routes; the cause is visible in `/health/ready`, database events and query spans.
- Shared IPv4 addresses (carrier NAT) can trip per-IP limits for unrelated users.

**Verification**
- Browser tests run in Chromium only, on one host. Other engines, assistive technology and physical devices aren't certified.
- HTTPS browser tests skip certificate checks; `curl --cacert` and Go tests verify the chain instead.
- IPv6 limits on AWS were checked without CloudFront (the test host had no IPv6).
- One Vitest case (`EditProductPage`, unknown save outcome) fails about 1 run in 10; not yet diagnosed.
- The largest JavaScript chunk (about 433 kB) is close to Vite's 500 kB warning.

**AWS stack:** development only; see [terraform/DESIGN.md](terraform/DESIGN.md#known-limits).
