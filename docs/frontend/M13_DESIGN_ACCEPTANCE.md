## Final design choices

| Area | Selected layout/interaction and reason |
|---|---|
| System and shell | Charcoal/mint semantic tokens, blue links, distinct status colors; system sans-serif fallback because no approved local Geist asset exists. Maximum 1280px, 16px phone/32px desktop gutters, 44px controls, restrained 180ms feedback. Compact sticky header measures its actual height; minimal recovery/proof pages omit shopping chrome. |
| Catalog/details | Four columns with full desktop space, two on tablet and one on narrow phones; opening the cart preserves the original catalog width and all card positions. Image/name/SKU/price/availability/Add hierarchy; long names wrap. No hover descriptions: explicit Quick View uses Dialog at ≥768px and a right Sheet below it. Each deliberate Add adds one; quantities belong in the full cart. |
| Mini-cart | Browsing routes only; ≥1920px right rail below the header in the outside margin, independently scrollable and 24px from the screen edge. The centered 1216px catalog retains four cards per row, open or closed. Below 1920px Cart opens a Sheet instead of resizing the catalog. Read-only quantities, estimate disclaimer, View Cart and Remove. Respect dismissal until owner presentation lifetime resets; no automatic phone overlay or focus stealing at breakpoint changes. |
| Full cart | Centered ≤900px single column, horizontal rows that reflow on phones, summary below. Real Radix-backed shadcn Select offers 1–10 and More… through 10000, separate Remove/Clear confirmation. Unknown estimates stay unavailable; pending/uncertain writes retain persistent guidance and block duplicates. No stock cap or reservation is implied by adding. |
| Shipping/checkout | Current cart only, summary right on desktop/above form on narrow layouts. Guest contact/US shipping is direct; signed-in shipping uses exclusive owned cards with prominent add/manage actions and inline save/select. Home is an optional label placeholder, not a saved default. Explicit accept/reject simulation → Review → deliberate Place → owned order route. |
| Recovery and orders | Compact guards retain original-choice Resume, deliberate pre-commit retirement and known-order fresh-cart blocking. Old order items/status stay off checkout. Orders show immutable snapshots and authoritative state, with rejection explaining consumed cart/reservation release and no automatic refill. Check Status/cancellation remain explicit; the preview runs no polling or recovery machinery. |
| Account/security | Narrow readable profile/security forms, button-styled account/address navigation, contextual readback after uncertain writes, unchanged-save disabled, address delete confirmation. Minimal forgot/reset/verification/email-change layouts retain the implemented requesting-account/password/mailbox-proof responsibilities. |
| Administration | Restrained centered landing; shared catalog/admin search presentation with separate context and URL handlers. Apply filters combines q/is_active/20–50–100 limit and resets offset; page-local counts/Previous–Next require no count endpoint. Product/SKU/status/unit-price/availability table scrolls locally on phones. Detail has secondary Edit/Back/Refresh, primary Adjust inventory quantity, and separate on-hand/reserved/available cards. Stock edits remain outside creation/editing. |

The preview adapts official shadcn Card, Alert, Badge, Skeleton, Separator, Dialog/Sheet, Select and Radio Group patterns; existing Button/Input are reused. InputGroup, Pagination, native table and semantic right Sidebar are lightweight compositions rather than unused generated providers/icon collections. Tailwind uses `tw:` with no Preflight. [Component provenance/license and dependency isolation](../../frontend/design-preview/README.md#components-and-isolation) are recorded with the source. Production component coverage is still owned by Tasks 7–10, verified by Task 11.

## Verification and measurable handoff criteria

| Check | Executed design result / production handoff |
|---|---|
| Responsive geometry | No document overflow at 360, 480, 768, 1024 and 1280px across storefront, checkout, orders, account/security and administrator layouts. Revised catalog/cart coverage adds 1919/1920/2560px: 1919 uses a Sheet, 1920+ retains four cards beside a nonoverlapping outside rail. Full-cart summary follows the list. Admin table is its own scroll region. |
| Overlay/input access | Keyboard Enter/Tab/Escape and trigger-focus return pass; mobile touch opens Quick View and cart without hover. Dialog/Sheet uses real Radix focus/dismissal behavior. Quantity replacement, More bounds, clear/cancel, error-summary focus, labelled fields and explicit payment radio selection pass. Production must preserve these with bounded reads and real controllers. |
| Contrast, focus and motion | Computed semantic text pairs ≥4.5:1 and control borders/focus ≥3:1 across the three opaque dark surfaces; dark text on mint passes. Rendered button-link color is explicitly checked to prevent global-link specificity regression. Three-pixel visible keyboard focus with dark gap, a focused action below the sticky header and reduced-motion transform suppression pass. Sample catalog/header controls meet 44px; 200% root-font stress has no document overflow. This is scoped checking, not formal WCAG/assistive-technology certification or full browser-zoom coverage. |
| Difficult states | Loading, empty, read error/retry, long content, missing images, unknown estimates, disabled/pending/uncertain writes, validation, unresolved/rejected/known-refresh/storage recovery and pending/rejected orders have reviewed layouts. Quantity changes block during uncertainty until explicit readback. Contextual checkout guards block new review; Resume retains the original demo rejection choice. |
| Flow and isolation | Guest accept/reject, signed-in inline address creation/selection, blank label preservation, order handoff/empty checkout, pending check/cancel, mini-cart dismissal/breakpoint/identity replacement and separate admin search/history context pass. Tests reject API/nonlocal/non-GET requests and verify no localStorage/sessionStorage writes. These are local React demonstrations, not ownership, durable recovery, payment or transaction acceptance. |
