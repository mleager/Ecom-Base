The [worker executable pool](../../frontend/tests/e2e/executables.ts) owns a fresh random `.cache/frontend-e2e/<id>` directory per worker/invocation. It lazily builds `fixtures`, normal `api`, and one integration `auth-control` binary, also used to run the isolated mail API. `GOTOOLCHAIN=local` and `.cache/go-build` retain native Go build caching. The pool never carries database URLs, credentials, tokens or mutable server state; runtime environment/private bundles remain per test. Workers default to four (`E2E_WORKERS` or `--workers` overrides, 1-16); each owns API port `18080+n` and a Vite server on `5173+n`, where *n* is Playwright's parallel index. The HTTPS group stays at one worker on port 18443. Source changes during a run require a restart; no custom cross-run binary cache is maintained.

Each backend fixture stops its own process before releasing the test, then queues removal of its marker-owned database/private bundle on a per-worker serial queue that overlaps the next test; the worker drains the queue before closing its executables. Failed process/database cleanup permanently marks the pool for retention. Worker shutdown waits for pending builds and removes only allowlisted files from its verified owned directory; partial builds are handled, unexpected entries and symlinks preserve data and fail visibly. Older directories are not swept. A terminated worker can leave resources requiring [explicit owned-fixture cleanup](FIXTURES.md#failure-handling-and-removal).

The reporter prints overall elapsed milliseconds plus summed numeric `build_ms`, `database_ms`, `startup_ms`, `journey_ms`, `cleanup_ms` and `build_commands`. Build time is charged to the first requesting test; journey time subtracts inline compilation. Per-test phase sums are not an exact wall-time decomposition: runner/Vite/worker teardown overhead is only in elapsed time. Only completed phase measurements are claimed after setup failure. Annotation shape/type/value limits prevent arbitrary worker values from reaching output. Existing privacy protections, zero retries and request/test deadlines remain unchanged. [Performance/isolation evidence](TEST_PLAN.md#harness-performance-and-isolation-progress) records the measured sample and final verification.
